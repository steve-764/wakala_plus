# Agent Deposits Statistics Toolkit

A Python toolkit that analyses the numeric columns of `data/agent_deposits.csv` (daily deposits in KES and transaction counts per agent). It cleans the data, tracks every rejected value with a reason, calculates descriptive statistics, flags outliers with the IQR rule, and writes a side-by-side report for the full data and the data with outliers removed.

## What it does

- **Loads and cleans a column.** `load_column(path, column)` converts a CSV column to floats. Values that cannot be converted are not dropped silently: each one is recorded as `(row_number, raw_value, reason)`, where the reason is `missing value` or `not a number`. Row numbers are file line numbers (the header is line 1).
- **Calculates statistics.** Mean, median, mode (returns every tied value, or none), sample and population variance, standard deviation, quartiles and IQR.
- **Detects outliers.** Values outside `Q1 - 1.5 x IQR` and `Q3 + 1.5 x IQR` are flagged, along with the date and agent they came from.
- **Reports.** `StatisticsAnalyzer` wraps a column and produces a report showing "all data" and "outliers removed" side by side. The data is sorted once when the analyzer is created and reused for every statistic.
- **Verifies against NumPy.** `compare_with_numpy(analyzer)` recomputes the statistics with NumPy and prints MATCH or MISMATCH for each.

### Method choices

| Choice | What the toolkit does | Why |
|---|---|---|
| Variance / std dev | Sample formula (divide by n - 1) by default; `sample=False` gives the population formula | The 40 days are a sample of how the agents behave, not their full history |
| Quartiles | Median of halves (Tukey's hinges); the middle value is left out of both halves when n is odd | Easy to follow and check by hand |
| Outlier fences | `k = 1.5` | Standard IQR rule |
| NumPy settings | `ddof=1`; quartile method `weibull` for odd n, `hazen` for even n | NumPy's defaults (`ddof=0`, `linear`) give different numbers, so they must be set to match |

## Setup

Requires Python 3.10 or newer.

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

`requirements.txt` needs only:

```
numpy
```

NumPy is imported inside `compare_with_numpy` alone, so everything else runs without it. Add `pytest` to the file if you prefer running the tests with pytest.

## Running the toolkit

Run from the project root, because the data path (`data/agent_deposits.csv`) is relative:

```bash
python stats_toolkit.py
```

This prints a report for `daily_deposits_kes` and `transactions`, and saves the same text to `output/stats_report.txt` (the `output` folder is created if it does not exist).

To use it from your own code:

```python
from pathlib import Path
from stats_toolkit import StatisticsAnalyzer, compare_with_numpy

analyzer = StatisticsAnalyzer.from_csv(Path("data") / "agent_deposits.csv", "daily_deposits_kes")

print(analyzer.report())            # full report
summary = analyzer.summary()        # dict of statistics (mean, median, q1, q3, outliers, ...)
cleaned = analyzer.without_outliers()   # a new analyzer without the flagged values
compare_with_numpy(analyzer)        # NumPy verification
```

## Running the tests

The tests use small, hand-checkable inputs (not the dataset) and cover empty input, even and odd lengths, ties in the mode, sample versus population variance, outlier detection and rejected values.

```bash
python -m unittest -v
```

or, with pytest installed:

```bash
pytest -q
```

A passing run ends with `Ran 11 tests` and `OK` (unittest) or `11 passed` (pytest). Run the command from the folder containing `test_stats_toolkit.py` and `stats_toolkit.py`.

## Outlier findings

Outliers were found in `daily_deposits_kes` only. `transactions` has none (fences 17.50 to 165.50).

For `daily_deposits_kes`, the IQR fences are **8,177.36 (lower)** and **29,006.28 (upper)**:

| Value (KES) | Date | Agent | Note |
|---|---|---|---|
| 96,500.00 | 2026-09-20 | AG-104 | Far above the upper fence |
| 88,400.00 | 2026-10-06 | AG-104 | Far above the upper fence |
| 1,200.00 | 2026-10-02 | AG-104 | Far below the lower fence |
| 29,060.99 | 2026-10-07 | AG-101 | Borderline, about 55 KES over the fence |

The first three are extreme and all belong to AG-104. The fourth is only just outside the fence, and a different quartile method could place it inside.

Effect on the statistics (35 values before, 31 after):

| Statistic | All data | Outliers removed |
|---|---|---|
| Mean | 22,400.00 | 18,349.65 |
| Median | 18,805.47 | 18,506.72 |
| Std dev (sample) | 18,111.32 | 3,180.63 |
| Min / max | 1,200.00 / 96,500.00 | 12,772.70 / 26,725.69 |

The median barely moves, while the mean shifts by about 4,000 KES and the standard deviation shrinks to about a sixth. This is why the mean and standard deviation of the raw deposits should not be trusted until the outliers are checked.

Data quality: 5 values were rejected in each column (blank cells, `-`, `n/a`, `abc`, and `12,40O`, which contains the letter O in place of a zero). The full list is in the report.

## Recommendations

1. **Verify the AG-104 values at the source.** Check the deposit records or receipts for 2026-09-20, 2026-10-02 and 2026-10-06. Because all three extreme values come from one agent, find out whether it is a reporting or data-entry problem.
2. **Add validation where the data is captured.** Reject or flag non-numeric entries (`-`, `n/a`, `abc`, thousands separators and typos like `12,40O`) and blank deposits at entry time.
